# Cross-Machine Coordination Backend

Research and proposed contract: [[04 Research/Cross-Machine Coordination Backend|Cross-Machine Coordination Backend research]]. External adoption: the Overwatch repository's Cross-Machine Git-fs Collaboration PRD. Planning only; implementation acceptance remains open.

## Goal

Give Overwatch a small, versioned git-fs backend contract for safe parallel work across machines: one configured authority accepts source changes and claims, git-fs atomically enforces installed fencing generations with its existing Git publication lock, durable operation receipts and accepted-state queries recover uncertain outcomes, and replicas import immutable revisions for local snapshots. Reuse Git merging, objects, compare-and-swap refs, guarded materialization, candidate verification, integrate and push. Overwatch owns lease lifecycle and authenticated routing; this repository owns backend enforcement and source integrity. Notifications are hints and disconnected replicas cannot accept shared writes. Implement as an opt-in extension without changing the frozen Native Mosaic Port parity baseline; this planning task changes documentation only.

## Acceptance

- [ ] BC1: Expose a versioned coordination capability and accepted-state contract bound to the configured project, canonical repository, authenticated authority and caller session; reject unsupported versions, aliases that change targets, borrowed sessions, and untrusted model-supplied identity before mutation. Uncoordinated installations retain their documented behavior.
- [ ] BC2: Install or advance a persistent project/claim fencing generation using expected-current-state checks under the same repository mutation lock used to validate and publish protected source changes. A takeover is acknowledged only after the newer fence is installed; stale, revoked, missing or wrong-scope authority cannot publish. Hooks or a separate preflight check alone never establish this guarantee.
- [ ] BC3: Persist caller-bound operation identity and outcome evidence across restart. Distinguish not dispatched, session commit only, accepted shared-live revision, disk synchronization and unknown outcomes; the same operation id with changed intent refuses, and lost acknowledgements reconcile without duplicating a mutation or treating an unshared session commit as accepted shared state.
- [ ] BC4: Provide a recoverable accepted-state query naming authority generation, shared-live source revision and operation outcome. Optional revision notifications are invalidation hints; dropped, duplicate or reordered hints and restart converge through authoritative state queries and verified Git ancestry. No generic durable event log or globally exactly-once delivery is required.
- [ ] BC5: Import verified immutable Git objects into a configured replica namespace and advance replica refs with expected-old-value checks. Validate project/source authority, object format, reachable object closure, named revision and allowed ref namespace before acknowledgement; refuse missing objects, malformed or unexpected refs and conflicts without modifying main, local live/session refs or another caller's history.
- [ ] BC6: Create and safely release exact-revision local snapshots from an accepted replica revision, preserving source bytes, modes and deletion semantics. Keep local materialization under existing overwrite guards; never copy .git-fs credentials, read-freshness state, locks, operation journals, snapshot capabilities or host-specific metadata between machines.
- [ ] BC7: Apply coordination fencing and stable outcome identity to all coordinated mutation surfaces, including capture, rollback, reconciliation that advances live, integration, undo and guarded push. Quiesce or reconcile an already-dispatched external push before acknowledging takeover; preserve current secret/review/candidate checks, expected remote-head checks, hook chaining and confirmed-remote evidence.
- [ ] BC8: Extend executable-neutral conformance fixtures with two repositories, concurrent sessions, conflicts, revocation races, restart at every durable boundary, lost acknowledgements, transport gaps, malicious identity/ref input and foreign disk edits. Native Windows and Unix runs identify exact executables/source revisions and prove no lost accepted commits, unauthorized shared publication, or destructive replica/materialization changes.
- [ ] BC9: Ship this coordination protocol as an explicit opt-in versioned extension with a capability gate and store-safe disable/rollback procedure. Preserve the frozen a830787f reference of Git-FS Native Mosaic Port and its existing parity acceptance; run the extension's shared contract fixtures against whichever implementation advertises it.
- [ ] BC10: Publish a documented adoption contract for Overwatch's Cross-Machine Git-fs Collaboration PRD, including authority/fence transitions, operation reconciliation, replica import and snapshot proofs. Activation remains blocked until both repositories pass their contract fixtures and a real two-machine acceptance identifies their serving builds; local test success alone does not claim deployment.
